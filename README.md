# 글결 — AI 블로그 콘텐츠 스튜디오

업체 정보로 네이버·티스토리용 초안을 생성하는 React 앱입니다. OpenAI Responses API는 Node 서버에서만 호출합니다.

## 실행 (Node 22.9 이상)

1. `npm ci`
2. `.env.example`을 `.env`로 복사합니다.
3. `.env`의 `OPENAI_API_KEY`에 본인 키를, `APP_ACCESS_CODE`에 길고 추측하기 어려운 이용 암호를 설정합니다. 키와 암호를 GitHub에 올리지 마세요. `VITE_` 접두사도 사용하지 마세요.
4. `npm start`
5. `http://localhost:3000`에서 이용 암호와 업체 정보를 입력하고 생성합니다.

API 이용 비용은 API 계정으로 발생합니다. 실제 키로 성공 응답을 확인하기 전까지 실서비스 연결 검증은 완료된 것이 아닙니다.

## GitHub에서 이어서 쓰는 경우

GitHub Codespaces 같은 Node 실행 환경에서는 위 명령을 터미널에서 실행할 수 있습니다. 3000번 포트는 비공개로 유지하고, `.env`는 그 실행 환경에서만 만드세요. GitHub 저장소 자체와 GitHub Pages는 이 Node 서버를 실행하지 않습니다. 기존 앱 주소에 반영하려면 해당 호스팅이 Node 서버 실행을 지원해야 합니다.

## 범위 및 제한

- 네이버는 일반 텍스트, 티스토리는 마크다운 소제목을 요청합니다.
- 사진 처리, 웹 검색, 자동 게시, 회원별 과금은 아직 없습니다.
- 개인정보나 업체 기밀은 입력하지 마세요. 생성 시 입력 내용이 OpenAI로 전송됩니다. API 요청은 `store: false`입니다.
- 이용 암호는 브라우저 메모리에서만 사용합니다. 서버가 설정되지 않으면 AI 호출을 차단합니다.
- 프로세스당 시간당 최대 20회, 동시 1회 호출 제한이 있습니다. 재시작·다중 서버에서 공유되지 않으므로 상용 서비스에는 회원 인증과 영속적인 사용량 제한이 필요합니다.
- 현재 `npm start`는 Vite 개발 미들웨어를 사용합니다. 비공개 개발·검증용이며, 공개 상용 배포 전 프로덕션 서버 구성이 필요합니다.
- 모델이 생성한 정보는 사실 검증되지 않았습니다. 게시 전에 확인하세요. 검색 순위나 AI 인용을 보장하지 않습니다.

검사: `npm test`, `npm run build`

## 사진 번호 및 삽입 안내 (첫 버전)

사진 최대 10장(JPG/PNG/WebP, 장당 10MB)을 브라우저에서 선택합니다. 사진에 설명을 입력하고 순서를 바꿀 수 있으며 번호는 삭제·정렬 후에도 다시 매기지 않습니다. 번호와 설명이 붙은 파일명으로 개별 다운로드할 수 있습니다.

생성 본문 문단 사이에 선택 순서대로 사진 안내를 분산 배치합니다. AI 사진 분석 또는 내용별 최적 위치 판단은 아직 없습니다. 사진과 설명은 OpenAI로 전송하지 않습니다. 본문 복사에는 사진 삽입 안내와 파일명이 포함되며 이미지 자체는 포함되지 않습니다. 블로그에서 직접 사진을 업로드한 뒤 안내 문구를 지워야 합니다. 완료 체크는 사용자의 작업 메모이며 실제 업로드 확인이 아닙니다.

새로고침·창 닫기 시 사진과 작성 내용은 사라집니다. 중요 사진 원본과 생성 글은 별도로 보관하세요. 이 버전에는 HTML 서식 복사 및 미넴 디자인 적용이 포함되지 않습니다.


## 범용 인터뷰 개선
업종별 쉬운 질문과 답변 반영 검토 기능을 추가했습니다. 사용법·수정 전후·제한은 [변경 기록](CHANGES-2026-10-26.md)을 참고하세요. 이번 브랜치는 7860c18에서 분기한 별도 검토본이며 Codespaces의 미업로드 변경을 포함하지 않습니다.


## 작성 전 핵심 확인 (2026-10-30)
- 업체 정보와 사용할 질문 답변을 입력한 뒤 ‘1. 자료 정리·핵심 질문 확인’을 누릅니다.
- 자료 목록은 서버가 입력 원문에서 만들며, AI는 애매한 표현·중요한 누락만 최대 3개 질문합니다.
- 선택지를 고르거나 직접 답한 뒤 ‘2. 답변을 반영해 글 작성하기’를 누릅니다. 모르는 질문은 비워둘 수 있습니다.
- ‘자료 확인 건너뛰고 바로 작성’은 작성 전 AI 호출을 생략합니다.
- 자료 확인과 글 작성은 각각 AI를 호출하며 기존 시간당 20회 한도를 공유합니다. 모델과 사용량에 따라 비용이 추가됩니다.
- 업체 자료를 수정하면 이전 확인 결과는 숨겨집니다. 작성 전 답변은 글 생성과 이후 게시 전 수정에도 전달됩니다.
- 인터넷 조사·독립적인 사실 검증 또는 GEO 성과 보장 기능이 아닙니다.
- 서버 모의 응답 테스트 25개 및 빌드 통과. 실제 유료 모델의 질문 품질과 사용자 브라우저 조작은 별도 실사용 확인이 필요합니다.


## 부족한 정보 인터넷 검색 (2026-10-30)
1. ‘부족한 정보 인터넷에서 찾기’에서 검색 범위와 찾을 내용을 적습니다.
2. 업체 정보는 공개된 공식 페이지·지도 주소(https://)가 필요합니다. 업종 일반 정보는 기준 링크 없이 검색할 수 있습니다.
3. 인터넷 검색 버튼은 추가 검색·모델 비용을 발생시키며, 기존 시간당 20회 요청 한도를 공유합니다. 공식 OpenAI web_search 도구를 사용합니다. OPENAI_SEARCH_MODEL로 검색 모델을 별도 설정할 수 있으며 기본값은 OPENAI_MODEL 또는 gpt-4.1-mini입니다.
4. 실제 완료된 검색 응답의 url_citation이 붙은 문단만 최대 5개 후보로 표시합니다. 업체 정보는 기준 URL과 같은 호스트의 인용이 있는 문단만 표시합니다. 기준 링크가 실제로 해당 업체의 공식 링크인지까지 기술적으로 보증하지는 않으므로 사용자가 확인해야 합니다. 검색일은 원문 정보의 기준일이 아닙니다.
5. 업체·조건·날짜와 기존 입력과의 차이를 확인한 뒤 사용할 후보를 체크하고 글 생성 또는 수정 버튼을 누릅니다. 기존 입력칸·글은 자동으로 덮어쓰지 않습니다. 일반 자료는 업체 운영 사실로 바꾸지 않도록 생성 지침을 적용합니다.
6. 선택 정보에는 서버 서명이 붙고, 업체명·업종·지역이 바뀌거나 검색 후 24시간이 지나면 다시 검색해야 합니다. 새 검색은 이전 선택을 대체합니다.
7. AI가 본문 섹션에 연결한 출처는 미리보기의 문단 및 복사 결과에 포함됩니다. 실제 인용의 적합성·검색 품질은 사용자가 확인해야 하며 누락된 근거 연결은 기존 점검 안내로 표시합니다.
8. 검색에는 명시한 공개 식별 정보와 검색어만 전송합니다. 전체 초안·사진·이용 암호·인터뷰 답변은 검색 입력에 포함하지 않습니다. 검색어에 비공개 정보를 넣지 마세요.
9. 공식 API 문서: https://developers.openai.com/api/docs/guides/tools-web-search
10. 모의 응답 자동 검사 33개 및 빌드로 연결·검증·출처 보존을 확인합니다. 실제 API 키로 하는 유료 검색과 브라우저 조작은 별도 실사용 확인이 필요합니다.
